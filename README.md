# 내일 시가 후보 찾기 (Tomorrow Open Candidates)

> **장 마감 후 새로 생긴 재료(뉴스·공시)를 모아, 과거에 같은 재료가 실제로 먹혔는지 채점해서 "내일 시가에 살 후보"를 좁혀주는 도구.**
> 판단 재료를 대령할 뿐, 매수 결정은 사용자가 한다.

🔗 **라이브 데모: [nl-stock-screener-afvg.vercel.app](https://nl-stock-screener-afvg.vercel.app/)**

## 왜 만들었나

직장인이라 장중 매매가 어렵고 **시가 매수 → 종가 매도**로만 거래한다는 전제에서 출발했다. 그래서 이 앱의 모든 수익률 지표는 **"다음 거래일 시가에 사서 종가에 팔았을 때"** 기준이다. (일반적인 "전일 종가 대비" 등락률은 밤사이 갭을 포함해 실제로 먹을 수 없는 수익이 섞이기 때문에 참고용으로만 병기한다.)

프레임워크는 **재료 · 차트 · 거래량 · 시황**(재차거시)이며, 자동화 가능한 부분(재료 수집·반복성 채점·시황·거래량 표시)은 앱이 하고, 차트 자리 판단과 최종 매수는 사람이 한다.

## 화면 (5개)

| 화면 | 하는 일 |
| --- | --- |
| **`/` 📌 내일 시가 후보** | 장마감 후 뉴스+공시 재료 → 반복성·신선도·시황으로 걸러 다음 거래일 후보 랭킹 + **거른 재료와 그 이유** |
| **`/score` 성적표** | 매일 후보를 저장해 다음 거래일 실제 등락으로 **누적 채점** (이 도구가 진짜 먹히는지 검증) |
| **`/backtest` 공시 백테스트** | 최근 N일 호재 공시 → 다음 거래일 시가매수 결과. DART는 과거 조회가 되므로 **축적 없이 즉시 검증** |
| **`/catalyst` 종목 재료 분석** | 한 종목의 급등 역사를 훑어 급등일의 등락률·거래량·시황·재료를 유형별로 정리 |
| **`/movers` 오늘의 특징주** | 상한가·거래량 1,000만주 이상 종목 + 급등 이유(뉴스). 오늘 시장의 주도 흐름 파악용 |

## 후보 선정 파이프라인 (`/`)

```
[뉴스] 네이버 검색 API — 장마감(15:30) 이후 재료성 헤드라인
[공시] DART — 오늘 공시 중 재료성만(계약·수주·자사주취득 등), 정정 제외
   │
   ▼ Groq(Llama)로 선별
   · "어제까지 없던, 새로 생기거나 사라진 구조적 변화"만 (예정·반복 이벤트 제외)
   · 악재성 사건이면 피해주가 아니라 반사이익 수혜주를 관련주로
   · stage: 확정(발표·통과·체결) vs 검토(추진·전망) — 검토는 감점
   │
   ▼ 반복성 채점 (핵심)
   · 뉴스: 같은 재료의 과거 에피소드를 찾아 관련주의 다음날 시가매수 수익
   · 공시: 그 종목의 같은 유형 과거 공시(DART 2년)의 다음날 시가매수 수익
   │
   ▼ 신선도 / 시황 / 거래량
   · 첫 등장 vs N번째 재탕 (재탕 + 과거 무반응이면 거르기)
   · 코스피 등락 + 오늘 부각 테마 매칭(강세 테마면 가점)
   · 최근 거래량 1,000만주+ 이력은 ⚡로 표시만 (거르지 않음)
   │
   ▼ 후보 랭킹 + 거른 목록  → 저장(하루 1건) → 다음날 /score에서 채점
```

## 설계 원칙

- **모든 지표는 시가매수 기준** — 실제로 체결 가능한 수익만 본다.
- **거른 이유를 보여준다** — 무엇을 왜 뺐는지가 무엇을 넣었는지만큼 중요하다.
- **자동화하지 않는 것** — 차트 자리, 재료의 임팩트 크기, 비중과 손절. 사람 몫으로 남긴다.
- **관련주 출처를 구분** — AI가 직접 지목(진한색) vs 테마 구성종목 보강(흐린색, 정확도 낮음).
- **검증을 항상 붙인다** — 새 규칙을 넣으면 과거 데이터로 먹히는지 확인한다. 실제로 이 과정에서 "게임 신작 출시는 선반영돼 안 먹힌다", "급락장에서는 호재 재료도 죽는다" 같은 결론을 데이터로 확인하고 필터에 반영했다.

## 데이터 소스 (전부 무료)

| 소스 | 용도 | 키 |
| --- | --- | --- |
| **네이버 검색 API** | 뉴스 재료·반복성 조회 | `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET` ([발급](https://developers.naver.com/apps/#/register), 무료) |
| **DART 전자공시** | 공시 재료·과거 공시 반복성 | `DART_API_KEY` ([발급](https://opendart.fss.or.kr), 무료) |
| **Groq (Llama 3.3 70B)** | 재료 선별·분류·관련주 추정 | `GROQ_API_KEY` ([발급](https://console.groq.com), 무료) |
| 네이버 금융 | 시세·테마·특징주 순위 | 불필요 |

> 구글뉴스 RSS는 데이터센터 IP를 차단해 서버·Vercel에서 실패하므로 네이버 검색 API로 교체했다.

## 실행

```bash
npm install
cp .env.example .env.local   # 위 키 입력
npm run dev                  # http://localhost:3000
```

Windows에서는 `앱-실행.cmd` 더블클릭으로 실행 + 브라우저 자동 오픈.

## 배포 (Vercel · 무료)

1. GitHub push → [vercel.com](https://vercel.com)에서 레포 import (Next.js 자동 감지)
2. Environment Variables에 위 키 3개 입력 → Deploy

> **로컬 전용 기능:** `/score`의 누적 데이터와 `/movers`의 날짜별 스냅샷은 로컬 파일(`data/`)에 쌓인다. Vercel은 서버리스라 파일이 유지되지 않으므로, 배포판에서는 그날 조회만 동작한다.

## 프로젝트 구조

```
src/
├── app/
│   ├── page.tsx              # 📌 내일 시가 후보 (메인)
│   ├── score/                # 후보 누적 채점
│   ├── backtest/             # 공시 백테스트
│   ├── catalyst/             # 종목 재료 분석
│   ├── movers/               # 오늘의 특징주
│   └── api/                  # tomorrow · score · backtest · catalyst · movers
└── lib/
    ├── tomorrow.ts           # 후보 파이프라인 (재료→반복성→신선도→시황)
    ├── dart.ts               # DART 공시 수집·분류·백테스트
    ├── news.ts               # 네이버 뉴스 검색
    ├── stocks.ts             # 회사명→종목코드, 테마 기반 관련주 보강
    ├── issues.ts             # 네이버 테마·구성종목(주도주·편입사유)
    ├── catalyst.ts           # 종목 급등 역사 분석
    ├── movers.ts             # 특징주 수집·일별 스냅샷
    └── radarLog.ts           # 후보 기록 + 누적 채점
```
